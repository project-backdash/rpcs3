# Spectator wire format

The spectator is a local consumer with no peer transport. One `PBD_SPECTATOR_CHANNEL` directory belongs to one process and set. Start at the real checkpoint reader's clean NPUB30009 character select, apply the native session seed sync, replay confirmed source digital words, and continue through natural VS in the same emulation generation. A stopped, slow, malformed or divergent consumer parks only its local owner until the launcher stops it. Empty input never becomes neutral input.

`spectator-session.json` uses schema `pbd-spectator-session-1`: `generation` is a positive decimal string <= 9007199254740991 (launcher binding token, distinct from native generation); `bindingDigest` is lowercase SHA256 of the launcher's canonical identity; `build`, `compat`, `titleId`, `emulatorSha256`, `checkpointSha256`, `recipeSha256`, `seed`, `stageId`, `leftCharacterRow`, `rightCharacterRow`, `roundsPerGame:3`, `syncEncoding:"pbd-sync-facts-v1"`, `syncDefinition:"pbd-peer-sync-v3"`. A fixed set gives the three picks as numbers (stage 0..0x25, rows 0..84) and binds them for every game. An in-game set (the fighters choose in the game's own select) gives all three as `null` or leaves them out; each game then binds the picks its own first intro applies. Any other mix is invalid. A full stream also declares `appliedEncoding:"pbd-applied-pad-v1"` and `inputPolicy` with booleans `sessionStartSkip`, `exitGate`, `phaseDelay`, integers `battleClockVersion`, `menuHashMask`. The native producer emits these policy values from owner storage; the consumer compares all simulation fields to its own actual configuration. `phaseDelay` documents the source's local input sampling delay and is not applied to a consumer without physical input sampling.

`checkpointSha256` in the local session identifies the actual local verified checkpoint, while the source `start.checkpointSha256` retains the publisher's own reader evidence. Installs may have different checkpoint bytes. Consensus uses the shared recipe, seed, fixed selection and policies; it does not replace the local reader check with source assertions.

Commands are immutable `spectator-control-N.json` in contiguous serial order, schema `pbd-spectator-control-1`, with `generation`, `bindingDigest`, `serial`, `type` and type fields:

- `begin_game`: `gameNumber`, `originBoundary`, `originCounter`, `kind` (`clean_character_select` for game 1, `natural_vs` thereafter), `stageId`, character rows and `roundsPerGame`. A fixed set repeats its picks. An in-game set sends the picks as `null` (or leaves them out) while they are unknown, or the lobby's agreed picks for that game, which the intro readback must then match. After a drawn game any `begin_game`, `game_picks` or `end_game` (the lobby's replay of the same number, which goes through the select again and may carry other fighters) ends the watch with a `stopped` report, reason `draw_replay`; the watcher does not follow the replay and never checks the replay's picks against the drawn game.
- `game_picks`: `gameNumber` (the game being watched), `stageId`, `leftCharacterRow`, `rightCharacterRow`, from the stream's `game_picks` marker. A cross-check only, never waited on: before the intro it is held for the readback, after it it must equal what the game applied. A disagreement refuses `game_picks_mismatch`; a malformed marker or another game number refuses `game_picks_invalid`.
- `end_game`: `gameNumber`, exclusive `finalFrame` digital sample watermark. This cannot execute an input or manufacture a result.
- `presentation`: `mode` (`watch`, `broadcast`, `analyze`), `hidden`, `catchUp`, `leftName`, `rightName`, `score:{left,right}`, `delayFrames`. A host request to show the game remains covered until actual intro readback. Catch-up speeds character select and battle scenes only; loading retains normal pacing. Those frames run as a correction's replayed ticks do: frame limit off, draws skipped, and one virtual vblank granted at each frame's boundary and served at once, with the 960 Hz vblank grid underneath. A virtual vblank runs the guest's own vblank handler, and every frame is still checked against the fighters' sync facts.
- `chat`: `visible`, `additions` containing at most 20 `{messageId,authorName,text}` records. Existing Unicode/plain-text bounds, five-line fade and immediate hide apply. Broadcast clears chat.
- `stop`: local containment and teardown.
- `waiting` (keeps a watch alive between games): `gameNumber` (1..19, the game the watch waits for: the one after the last game it played, or 1 before any) and `phase` (`between_games` while the room's table is between games; `next_game` while the table plays a game whose `begin_game` has not been sent yet, that is its select and VS load, whose inputs reach the watcher only at that game's start). The native input wait is 60 s from the start of a wait (`spectator_buffer_timeout`); a `waiting` that names the game the watch waits for, while it waits for it (its last game ended, or none began, and no input of the next one is held), moves that deadline to its own arrival plus 60 s, so the launcher sends one at least every 20 s while either phase lasts. A stall still ends: 60 s after the last `waiting` without the game beginning refuses `spectator_source_stalled`, and 10 minutes of one wait without a game, however many came, refuses `spectator_wait_limit`. The awaited game's `begin_game` starts the wait for its first input afresh (60 s from its arrival, and a new 10-minute limit), however long the gap before it lasted. While it counts, the cover says what the watch waits for ("BETWEEN GAMES · Game 2 starts when both players are ready." / "NEXT GAME · The players are choosing their fighters for game 2."), until that game's `begin_game`. A `waiting` for another game, one that arrives while a game is still playing, or one after a drawn game changes nothing; a malformed one (another phase, a game number outside 1..19) refuses `waiting_invalid`.
- `watch_ui` (the watcher's own screen; `rpcs3/Emu/Cell/pbd_spectator_ui.h`): the whole screen at once, each one replacing the last. Required: `revision` (integer, strictly higher than the previous `watch_ui`'s; pad events echo it), `bar` (boolean: the button bar), `firstTo` (0..10; the score line "Game 2 · Kai 1 – 0 Rook · first to 2" and the VS cards' set length, 0 draws no score line), `unread` (0..99: the count on Chat). Optional, absent or `null` for none: `preview` `{id, author?, text}` (a new chat line: `id` 1..64 printable ASCII, `author` 0..16 bytes, `text` 1..160 bytes; shown for 6 s from the moment an `id` first shows (one that arrives in an intro, at a K.O., between rounds or on the cover waits for the fight), fading over the last second; the same `id` again keeps its time); `chat` `{tabs?: [1..16 bytes] x0..4, tab?: index, to?: 0..48 bytes, lines?: [{author?: 0..16, text: 1..160, system?: boolean}] x0..8 (newest last), quick?: [1..32 bytes] x0..6, selected?: index into quick}` (the chat panel open over the match; present = open); `profiles` `{left: {name: 1..16, lines?: [0..48 bytes] x0..4}, right: {...}}` (open = present); `cards` `{left: {language: 0..16, region: 0..32}, right: {...}}` (the watcher's VS cards). All text is UTF-8 without control characters. The names and the score come from `presentation`, the game number from the game being watched. A malformed `watch_ui` or a revision that does not grow refuses `watch_ui_invalid`. The screen shows only while the watched game has a fight on screen (pending phase 5 of scene 16/17), after its intro readback, outside `broadcast` and while `hidden` is false: never on the cover, in the intros, at a K.O. or between rounds. The game owns the Quick-line highlight: a newly opened chat (or other `quick` lines or another `selected`) puts it on `selected`, the same panel sent again keeps the watcher's highlight, Left/Up and Right/Down move it. What the watcher sees (`pbd_spectator_overlay`, 1280x720 canvas, PBD panels and glyphs, no game art): while a fight is on screen, the button bar at the bottom left (`{circle} Stop Watching`, `{square} Chat` with a gold count while `unread` > 0, `{r2} Profiles`; with the chat open `{cross} Send` when there are Quick lines, `{circle} End Chat`, `{triangle} Quick Lines`, `{l1}/{r1} Tab` with two or more tabs; with the profiles open `{r2} Close Profiles`, `{square} Chat`, `{circle} Stop Watching`), the score line at the bottom right, the preview above the bar while the chat is closed, the chat panel over the left of the match (tabs, the newest lines that fit with authors in gold and lobby lines dim, `to`, "Type anything else in the launcher's chat.", the Quick lines as chips with the highlighted one in gold), or the two profiles side by side. The status band ("Watching · names · About n s behind") is drawn only for a launcher that sends no `watch_ui`. A launcher that sends `watch_ui` should stop sending `chat` (the corner lines): the preview and the chat panel replace them. The phase is the watched game's own: the pending phase read at each spectator boundary, so the bar appears when round 1 starts and hides for every intro, K.O. and round result. With `firstTo` > 0 the watcher's game also draws the VS cards (`pbd::vs_cards`: the presentation names, `cards` origins, `GAME n`, `FIRST TO n · 3 ROUNDS`, the stage that game loads) over its cover while the watched game shows its VS screen (scene 10).

Input is immutable `spectator-input-N.bin`, packet serial monotonic across games. Header is 96 bytes: magic `PBDSPC1\0` at 0, binding generation u64 LE at 8, game u32 at 16, first game-local digital ordinal u32 at 20, count u16 at 24 (1..120), flags u16 at 26, serial u32 at 28, binding SHA256 32 bytes at 32, payload SHA256 32 bytes at 64. Flag 0 is the legacy 64-byte row. Flag 1 is an 80-byte row and is required when the manifest declares applied encoding.

Each row starts with two eight-byte raw pad records (u16 buttons LE, six zero reserved bytes). The next 48 bytes are the native pre-input sync fact record: boundary u32, segment u32, synchronized game-flow counter u32, scene u32, hash mask u32, exit-gate hold u32, then three combat u64 words; all little endian. Flag 1 appends two eight-byte actual source applied pad records. Raw records preserve the synchronized START-held chain; applied records independently prove the words the source's stock handlers actually saw after neutral/START filtering.

The native producer's `confirmed_inputs` carries side `data` (8 bytes/sample), `pairedData` (`pbd-paired-pad-v1`, 16 bytes/sample), `appliedData` (`pbd-applied-pad-v1`, 16 bytes/sample), and `syncFacts` (`pbd-sync-facts-v1`, 48 bytes/sample, definition `pbd-peer-sync-v3`); each object has base64url data and SHA256 digest. Chunks are 48 samples so the full extension remains within the lobby 8 KiB envelope. Paired and applied words come from completed, confirmed source rows, including corrected passes.

Peers can execute different numbers of loading updates before their alignment barrier. Use the actual left publisher's complete confirmed two-port timeline as the canonical spectator transcript. The right publisher attests overlapping masked native boundary hashes. Do not pair compressed loading ordinals blindly, or fill absent records with invented neutral samples. Canonical relay packets may repeat the identical 16-byte paired applied record on both side envelopes; private intake stores it once.

Reports are immutable `spectator-native-N.json`, schema `pbd-spectator-consumer-2`, host `generation`, `nativeGeneration`, `bindingDigest`, game number and report serial. `prepared` proves native clean character select and actual checkpoint/executable identities. `received` advances only receipt. `ready` proves actual applied first intro and carries that game's applied `stageId`, `leftCharacterRow`, `rightCharacterRow` (equal to the set's picks for a fixed set; the game's own choice for an in-game set, per game). `consumed` follows ordinary two-port native post readback, matching source applied words and existing three-region masked peer hashes; its `through` and `hashCheckedThrough` are equal game-local ordinals, while `boundaryThrough` is the last actual native boundary plus one. Ordinals need not equal native boundary differences because alignment holes are explicit. `ended` additionally requires the real local match end, winner/three-round readback and the exclusive source watermark. A drawn game (winner bytes naming neither side, both fighters at three rounds on the same final round, read as the lobby path reads it) ends with `outcome:"draw"`; the cover then shows "This game is replayed after a draw. Watching resumes with the next game." and the watch closes. `stopped` (`reason`, `through`) ends the watch without a fault: `draw_replay` at the next `begin_game`, `game_picks` or `end_game` after a draw, or when nothing arrives within the 60 s input wait after it (a `waiting` control never extends a watch that a draw closed). `refused` hides and contains the local process.

Watcher presses are immutable `spectator-pad-N.json`, a contiguous serial of their own starting at 1 (separate from the reports), schema `pbd-spectator-pad-1`: `{schema, bindingDigest, generation (the launcher binding token), serial, button, chatOpen, shown, uiRevision[, quickLine]}`. `button` is `circle`, `start`, `square`, `r2`, `triangle`, `l1`, `r1` or `cross`; `chatOpen` says a `chat` panel was open (Circle then means End Chat, otherwise Stop Watching); `shown` says the screen was on screen; `uiRevision` is the revision of the `watch_ui` the press was made on (0 before any); `quickLine` (with `cross` only) is the highlighted index into that revision's `quick`. Only presses count (a button that goes down; one held when watching starts is not a press). Start requests local catch-up to the live game in either display state. While the screen shows, Circle, Start, Square, R2, Triangle, L1 and R1 report, and Cross reports only with the chat open and at least one Quick line; while it does not (the cover, intros, a K.O.), Circle and Start report. Select, L2, L3, R3 and the directions never report. The first controller read only tracks held buttons; reads claimed by the in-game Settings menu also emit no events or navigation, so releasing the menu cannot turn a held button into a fresh press. The controller is read by the host (`pbd::pads::spectator_watch::poll` in `rpcs3/Input/pbd_pad_spectator.cpp`, handler instances of the watcher's own for XInput, DualShock 4, DualSense and SDL pads, each with its default mapping), never through the game's ports, which stay virtual and neutral; it reads nothing while the game window does not have the focus (whatever the background input setting: the launcher reads the same pad while it has the focus), a button held when the game window takes the focus is no press until it is released, and keyboards are not read. A pad file that cannot be written is dropped and the watch goes on.

`PBD_SPECTATOR_EXECUTED_TRACE` optionally names an exclusive absolute JSONL output. A `spectator_frame` row is written after native commit and contains game ordinal, actual boundary, raw pad words, actual injected words, and SHA256-bound syncFacts generated from observed local state. This supports independent comparison to the source raw/applied transcript and both players' masked hashes.

Required launch policy uses the same pinned fighter fixture and function probes: session/round lifecycle, synchronized seed, START skip, battle clock 2, stage/voice sync, exit gate, both virtual neutral LDD pads with Null handlers in the isolated profile, and tick instrumentation for real sync hash reads. Product keyed draws are explicitly off. Keep `SESSION_BLOCKING_LOADS` off as in the fighter launch policy; waits inside loading can depend on progress of the main/render loop. No `PBD_PEER_*`, Practice, replay controls, takeover or set channel is admitted in the spectator. A slower local loader or hash mismatch is an explicit local refusal and cannot influence the fighters.

`inputPolicy.keyedDraws` is a required boolean whenever a native start or private manifest carries inputPolicy. The producer reads the immutable runtime hook configuration via `pbd::fn_hook::keyed_draws_enabled()`. Relay normalisation and the private binding retain it; missing or non-boolean values refuse instead of assuming off. The watcher compares it to that same native accessor before clean-start preparation. Native reason `spectator_keyed_draws_mismatch` logs "This spectator uses a different game setting (keyed draws)." The product watcher rejects keyed-on sources with the same sentence before creating its private profile.

The existing peer clean-start options barrier appends the actual keyed boolean to its full-width FNV digest, without changing the peer packet version, length or other fields. Both same-build players must agree before dispatching the session's first tick. A disagreement retains `session_options_mismatch` and reports "The other player uses a different game setting (keyed draws or match options)." The digest cannot identify which option differed, so the reason names both possibilities. Lobby sessions cannot disable this options barrier. The launcher's compatibility policy digest refuses a mismatch separately, before native loading. The producer, relay and binding change together; recordings made before the field existed carry no keyed value and are not backfilled.

## Standby and bind

A watcher can start before there is a set to watch, so that a player waiting in line is watching within moments of the set starting. The launcher starts it as any watcher (the same profile, checkpoint, recipe, start-state and input policy switches, `PBD_SPECTATOR_CHANNEL` naming an empty channel directory) with `PBD_SPECTATOR_STANDBY=1` and without `PBD_MATCH_SEED`. The standby runs the standard policy: `PBD_SESSION_START_SKIP=1`, `PBD_SESSION_EXIT_GATE=1`, `PBD_BATTLE_CLOCK=2`, `PBD_SESSION_MENU_HASH=0`, keyed draws off. A seed in its environment, or any mode a watcher may not run, is a setup failure (`spectator_standby_conflict`).

At its first boundary, before the session start sync, the standby proves this install's clean character select: the checkpoint this process booted, the pinned game code and native tables, the recipe, scene 3/44, three rounds and both button maps. It then writes `spectator-standby.json` and holds that boundary, as a fighter's session start holds it while the other player loads:

`{"schema":"pbd-spectator-standby-1","type":"ready","nativeGeneration":"<u64 decimal>","owner":<main PPU id>,"origin":0,"scene":3,"subscene":44,"checkpointSha256":"<hex>","emulatorSha256":"<hex>","recipeSha256":"<hex>","inputPolicy":{"sessionStartSkip":true,"exitGate":true,"keyedDraws":false,"battleClockVersion":2,"menuHashMask":0}}`

The bind is the set's `spectator-session.json`, exactly as a watcher started for that set reads it, written whole into the channel (beside it, then moved or linked into place). The standby polls for it every 10 ms; a read the system denies while the file is moved into place is tried again for up to a second, and a manifest that cannot be read or parsed ends the standby with `spectator_manifest_invalid`. It then takes the manifest's seed as the session seed and accepts the manifest as a launched watcher does: the watcher mode, the emulator digest, keyed draws, and the input policy, which must equal the standby's own. The seed is applied by the session start sync at the same boundary, exactly as for a watcher launched with it, and the watch continues with its `prepared` report and the usual controls and input. The launcher compares the set's policy and the reported digests before it binds; a set it cannot bind gets a watcher started for it instead.

A standby that ends without being bound, or whose bind is refused, writes `spectator-standby-end.json` instead: `{"schema":"pbd-spectator-standby-1","type":"ended","reason":"<reason>","waitedMs":<n>}`. Reasons: `clean_start_unverified`, `report_publish_failed`, `spectator_manifest_invalid`, `emulation_stopped` (the launcher closed the game) and the launch refusals `spectator_mode_conflict`, `spectator_emulator_build_mismatch`, `spectator_keyed_draws_mismatch`, `spectator_input_policy_mismatch`, `spectator_channel_invalid`, `spectator_executed_trace_invalid`, `spectator_executed_trace_collision`. Neither standby file is ever replaced. The output stays silent while the standby waits: the game's sound opens after the start sync, and a hidden watch keeps it muted.
